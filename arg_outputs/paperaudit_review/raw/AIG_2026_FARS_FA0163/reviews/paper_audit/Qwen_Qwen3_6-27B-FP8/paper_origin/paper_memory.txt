# Global Summary
The paper addresses the inefficiency of redundant execution feedback during test-time scaling for code generation. It proposes Execution-Signature Recycling (ESR), a training-free method that clusters candidate programs by their execution signatures (failing test IDs and error types) and conditions subsequent generations on a deduplicated failure bank. Evaluated on HumanEval+ using Qwen2.5-Coder-7B-Instruct under a fixed 16-generation budget, ESR achieves a mean Pass@1 of 87.60%. However, it does not significantly outperform the Self-Debug baseline (86.99%), with a 95% confidence interval of [−0.81, 2.24]. The authors report this as a negative result, concluding that for strong code models, per-sample self-debugging is sufficient and cross-sample feedback aggregation offers no reliable additional benefit. The paper notes it was generated by an automated research system and provides a public code repository.

# Abstract
- Problem: Redundant execution feedback across multiple failing candidates wastes model context during test-time scaling.
- Method: Execution-Signature Recycling (ESR) clusters candidates by execution signatures and conditions new generations on a deduplicated failure bank.
- Evaluation: HumanEval+ benchmark, Qwen2.5-Coder-7B-Instruct model, fixed 16-generation budget.
- Key Results: ESR achieves a mean Pass@1 of 87.60%. Self-Debug baseline achieves 86.99%. The 95% confidence interval for the difference is [−0.81, 2.24], which includes zero.
- Conclusion: Negative result indicating per-sample self-debugging may be sufficient for strong models; cross-sample aggregation does not yield reliable benefits.
- Caveat: Paper generated by an automated research system; code is publicly available.

# Introduction
- Context: Test-time scaling via best-of-N sampling improves code generation. Execution feedback methods like Self-Debug, Reflexion, and Self-Refine typically refine candidates individually without sharing information.
- Hypothesis: Candidates often fail for similar reasons; deduplicated feedback could reduce redundant exploration.
- Method: ESR aggregates execution feedback using signature-based clustering to provide a compact failure bank for subsequent generations.
- Evaluation Scope: HumanEval+, Qwen2.5-Coder-7B-Instruct, 16-generation budget.
- Key Results: ESR mean Pass@1 is 87.60% vs. Self-Debug 86.99%. 95% CI is [−0.81, 2.24].
- Contributions: Proposes ESR, conducts rigorous evaluation with pre-registered decision rules and paired bootstrap CIs, and reports a negative result favoring simpler per-sample feedback.

# Method
- Problem Formulation: Generate a program passing all unit tests for a given task, maximizing Pass@1 under a fixed budget of N=16 candidates.
- Execution Signatures: Defined as the set of failing test outcomes containing test ID and error type. Passing tests are excluded to keep signatures compact.
- Two-Round Procedure: Budget split into two rounds of 8 candidates each.
  - Round 1 (Exploration): Sample 8 candidates, execute against base tests, record signatures.
  - Failure Bank Construction: Cluster by exact signature equality. Bank entries include cluster count, failing test IDs, and up to K=2 examples (input, expected output, observed output/traceback). Top M=3 clusters by frequency are serialized into a failure bank with a 900-token budget.
  - Round 2 (Exploitation): Prompt model with task specification, failure bank, and instruction to avoid documented failures. Sample 8 new candidates.
  - Selection: Pool all 16 candidates, select the one maximizing base-test pass rate, with ties broken by fewer failing tests.
- Design Rationale: Aggregates cross-candidate information to identify common failure patterns, contrasting with per-sample refinement. Uses deterministic, unit-test-grounded signatures instead of semantic deduplication.

# Experiments
- Setup: HumanEval+ (164 Python tasks). Base model: Qwen2.5-Coder-7B-Instruct. Fixed 16-generation budget. Sampling: temperature 0.7, top-p 0.95, max 1024 tokens. Three random seeds (42, 123, 456). Mean ± standard deviation reported.
- Baselines: Best-of-16 (pure parallel sampling), Self-Debug (8 initial candidates + 8 debug revisions per candidate).
- Evaluation Protocol: Select candidate maximizing base-test pass rate. Evaluate on HumanEval+ augmented tests. Metric: Pass@1. Statistical significance via paired bootstrap CIs over 492 task-seed pairs.
- Main Results: Best-of-16 mean Pass@1 = 85.98 ± 0.50. Self-Debug = 86.99 ± 0.70. ESR = 87.60 ± 1.27. ESR vs Best-of-16: +1.63pp (significant, 95% CI [0.41, 3.05]). ESR vs Self-Debug: +0.61pp (not significant, 95% CI [−0.81, 2.24]).
- Signature Statistics: ~68% of tasks (111/164 average) have all Round 1 candidates passing, resulting in empty failure banks. ESR only applies to ~32% of tasks. Median unique signatures among failing tasks is 1.0.
- Variance Analysis: ESR inter-seed variance (std=1.27) is higher than Best-of-16 (std=0.50) and Self-Debug (std=0.70). Per-seed performance is inconsistent: +2.44pp over Self-Debug on seed 42, −0.61pp on seed 123, and a tie on seed 456.
- Discussion: Strong base model limits improvement room; high all-pass rate restricts ESR utility; per-sample feedback may suffice when failure modes are diverse.
