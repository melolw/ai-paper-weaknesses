# Innovation & Motivation Report

## 1. The Authors' Claimed Contribution
- **Core Problem**: Large Language Models frequently ignore explicitly provided definitions or glossaries, defaulting instead to conventions memorized during pretraining. This leads to internally consistent but externally incorrect solutions, particularly in mathematical reasoning where multiple valid conventions coexist (e.g., different convolution definitions).
- **Claimed Gap**: As stated in the Related Work section: *"Existing methods improve reasoning quality but do not address binding to specific conventions."* The authors argue that prior work focuses on general instruction compliance, generic reasoning enhancement (CoT, self-consistency), or code contracts, but lacks a mechanism to *discriminatively verify* convention interpretation before the main reasoning step.
- **Proposed Solution**: Definition Unit Tests (DUT), a training-free prompt wrapper that prepends auto-gradable, discriminative verification questions (checks) derived from the glossary. The method includes an engagement-matched control (neutral checks) to isolate the causal effect of discriminative content from generic benefits of additional tokens or computation.

## 2. Comparative Scrutiny (The "Trial")

### vs. TDD Governance for Multi-Agent Code Generation
- **Identified Overlap**: Both frameworks repurpose formal verification/tests as pre-computation constraints to force LLMs to adhere to external rules rather than internal priors. The TDD paper uses validation gates and phase-ordered workflows for code generation; DUT uses discriminative checks for mathematical convention adherence.
- **Manuscript's Defense**: The manuscript does not directly cite this specific work, but addresses the broader category in Related Work: *"DUT shares the philosophy of using tests to verify behavior but applies it to mathematical reasoning rather than code generation."* It further differentiates by emphasizing that its checks are *discriminative* (answers differ under alternate conventions) and validates this via an engagement-matched control, rather than relying on workflow orchestration or multi-agent architectures.
- **Reviewer's Assessment**: The defense is conceptually sound but highlights an *application-oriented* novelty rather than a structural one. The core mechanism (pre-reasoning verification gates) is functionally identical to test-driven governance. The manuscript successfully carves out a niche by focusing on *semantic convention disambiguation* and proving the necessity of discriminative (vs. neutral) checks, but the underlying "test-as-constraint" paradigm is not novel.

### vs. CROP: Token-Efficient Reasoning in Large Language Models via Regularized Prompt Optimization
- **Identified Overlap**: Both employ constraint-driven prompt engineering to override default LLM behaviors. CROP uses automated regularization to control token verbosity; DUT uses manual discriminative checks to control convention drift. Both explicitly reject computationally expensive baselines (majority voting/verbose CoT) in favor of prompt-level steering.
- **Manuscript's Defense**: The manuscript positions DUT within *"Prompt Engineering for Reasoning"* and explicitly contrasts it with methods that only improve general reasoning quality. It defends its approach by introducing the engagement-matched control: *"Condition B is essential to isolate the effect of discriminative content from generic benefits of additional computation or tokens."* This directly counters the risk that DUT's gains are merely due to added prompt length or computational overhead, a concern central to CROP's efficiency focus.
- **Reviewer's Assessment**: This is a strong methodological defense. The manuscript successfully demonstrates that the *type* of constraint (discriminative semantic verification) matters more than the *presence* of constraints or additional tokens. However, the broader paradigm of "prompt-level constraint injection to steer generation" remains shared. The novelty lies in the rigorous experimental isolation of discriminative effects, not in the prompt engineering architecture itself.

### vs. MathCoder: Seamless Code Integration in LLMs for Enhanced Mathematical Reasoning
- **Identified Overlap**: Both target reliability in mathematical reasoning by introducing explicit verification steps. MathCoder uses code execution to ground derivations; DUT uses prompt-level checks to ground convention interpretation. Both assume that unguided LLM reasoning is insufficient without externalized verification loops.
- **Manuscript's Defense**: The manuscript does not cite MathCoder but implicitly differentiates through its error analysis and problem formulation. It notes: *"Under DUT, remaining errors are primarily computational or parsing failures, not convention confusion."* It further clarifies in the Convolution family analysis that *"29% of Llama's errors here are arithmetic/reasoning errors, not convention errors,"* explicitly separating semantic convention binding from computational verification.
- **Reviewer's Assessment**: This is a substantive and well-supported distinction. MathCoder addresses arithmetic/logical correctness via external tooling and fine-tuning; DUT addresses semantic ambiguity via in-context learning and zero-shot prompting. The manuscript correctly identifies convention drift as a distinct failure mode that code execution cannot solve. This strengthens the motivation significantly, as it targets a gap that execution-based methods inherently overlook.

## 3. Novelty Verdict
- **Innovation Type**: Application-Oriented / Methodologically Rigorous Incremental
- **Assessment**: The paper successfully defends its contribution against broader prompt engineering and verification literature by narrowing its scope to a specific, under-explored failure mode (convention drift) and backing it with a rigorous control design. It does not propose a new mathematical theory or a fundamentally new architecture. Instead, it introduces a carefully controlled prompt engineering technique that isolates the causal effect of discriminative verification. The existence of similar works (test-driven prompting, constraint optimization, execution verification) does not invalidate the motivation, but it does frame the novelty as *empirical and methodological* rather than *algorithmic*. The paper survives the comparison by proving that discriminative checks are necessary and sufficient for convention binding, a claim not established by prior constraint-based or reasoning-enhancement methods.
  - **Strength**: The engagement-matched control design is a significant methodological advance that effectively isolates the effect of discriminative content from generic token/computation benefits. Clear empirical separation between convention errors and computational errors strengthens the problem formulation.
  - **Weakness**: The core mechanism (pre-computation verification checks) is conceptually aligned with existing code-contract and constraint-prompting literature. Reliance on a single synthetic benchmark and manual check design limits generalizability and scalability. The novelty is more about rigorous experimental validation and domain adaptation than fundamental methodological breakthrough.
