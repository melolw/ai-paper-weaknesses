# Global Summary
This paper investigates whether entropy dynamics can serve as reliable execution-free selection signals for best-of-N code generation. The authors adapt the Entropy Dynamics Instability Score (EDIS), originally designed for math reasoning, into a normalized variant (nEDIS) and test it against pre-registered success criteria. Evaluation is conducted on HumanEval (164 problems) and MBPP (378 problems) using DeepSeek-Coder-6.7B-Instruct with N=32 sampled candidates. The study reports a clear negative result: nEDIS fails the pre-registered criterion and underperforms random first-sample selection by 12.8–27.5 percentage points. A primary failure mode is entropy sparsity, with 88.3% of per-token entropy values being exactly zero, which breaks the spike-detection mechanism. The optimization required to improve performance (nEDIS_v2) inverts the original selection direction and multiplies by sequence length, contradicting the initial hypothesis and suggesting the method captures length bias rather than meaningful uncertainty dynamics. The authors release code and data to prevent redundant effort and advocate for alternative execution-free selection approaches.

# Abstract
- Tests whether entropy dynamics (EDIS) can provide execution-free selection signals for code generation via an adapted method called nEDIS.
- Uses pre-registered success criteria to rigorously evaluate the approach.
- Reports a clear negative result: nEDIS fails the criterion and underperforms random first-sample selection by 12.8–27.5 percentage points on HumanEval and MBPP.
- Identifies entropy sparsity as a key failure mode: 88.3% of per-token entropy values are exactly zero, undermining spike detection.
- Notes that optimizing nEDIS into nEDIS_v2 contradicts the original hypothesis, indicating the method captures length bias rather than meaningful entropy dynamics.
- States the paper was generated by an automated research system and provides a public code repository.

# Method
- Defines the best-of-N code selection problem: generate N candidates from a prompt and select one using a scoring function f(y) without execution.
- Reviews EDIS background: detects burst spikes (progressive entropy rise) and rebound spikes (sharp entropy recovery) in per-token entropy trajectories. Original EDIS score combines spike counts with entropy variance; lower scores indicate more stable/reliable reasoning.
- Introduces nEDIS: normalizes EDIS for variable-length code using nEDIS(y) = s(y) * (1 + CV_H^2), where s(y) is the length-normalized spike rate and CV_H is the coefficient of variation of entropy.
- Introduces nEDIS_v2: nEDIS(y) * T, using argmax selection (higher score = selected). This inverts the original argmin direction and multiplies by sequence length T.
- Pre-registered success criterion: nEDIS must significantly outperform both confound baselines (Length-only and CV_H) on both benchmarks (HumanEval and MBPP) at p < 0.05. Failure to beat either baseline on either benchmark refutes the hypothesis.
- Baselines: Trivial baselines include Greedy decoding and First-Sample random selection. Confound baselines include Length-only, CV_H, Mean_H, and Self-Certainty (equivalent to Mean_H in this setting).

# Experiments
- Setup: Uses DeepSeek-Coder-6.7B-Instruct. Benchmarks are HumanEval (164 problems) and MBPP (378 problems), evaluated on both base and EvalPlus augmented test cases. Generates N=32 candidates per problem with temperature 0.8, top-p 0.95, and maximum 512 new tokens. Statistical significance tested via one-sided paired bootstrap with 1000 resamples.
- Performance (pass@1): Greedy achieves 71.3% (HumanEval) and 77.8% (MBPP). First-Sample achieves 68.9% (HumanEval) and 69.0% (MBPP). Length-only achieves 35.4% (HumanEval) and 66.4% (MBPP). CV_H achieves 28.1% (HumanEval) and 34.1% (MBPP). Mean_H/Self-Certainty achieves 33.5%/20.6%. Original nEDIS achieves 25.0% (HumanEval) and 26.5% (MBPP). Optimized nEDIS_v2 achieves 56.1% (HumanEval) and 41.5% (MBPP).
- Significance testing: nEDIS_v2 vs Length-only shows +20.7pp (p < 0.001) on HumanEval but -24.9pp (p = 1.0) on MBPP, failing the pre-registered criterion. nEDIS_v2 vs First-Sample shows -12.8pp (p = 1.0) on HumanEval and -27.5pp (p = 1.0) on MBPP, confirming entropy-based ranking actively harms selection.
- Analysis: 88.3% of per-token entropy values are exactly 0.0, causing extreme sparsity that makes burst/rebound detection noisy. The optimization to nEDIS_v2 requires inverting selection direction and multiplying by length, contradicting the original "low instability = reliable" hypothesis and indicating length bias capture. Original nEDIS performs worst among all methods.
